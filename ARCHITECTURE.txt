LEGEND
  -->  sends data to / calls
  <--  receives data from
  <-> bidirectional
  [IPC] Electron inter-process communication
  [stdio] Python subprocess stdin/stdout pipe
  [FS]  direct filesystem read/write


================================================================================
  LAYER 1 — ENTRY & PROCESS BOOTSTRAP
================================================================================

src/main/main.js
  ROLE: Electron main process. App entry point. Owns window lifecycle,
        spawns Python, and routes all IPC between renderer and Python.
  OWNS:
    - BrowserWindow instances (dashboardWindow, orbitWindow)
    - pyProcess (child_process.spawn handle)
    - dbFilePath, logFilePath (computed from app.getPath("userData"))
    - spawnAttempts[] (crash backoff guard)
  DEPENDS ON (Node built-ins):
    - electron  { app, BrowserWindow, ipcMain, shell, dialog }
    - path, fs, child_process.spawn, readline
  READS FROM [FS]:
    - focusModemsgs.txt  (root dir, parsed for overlay messages)
    - settings JSON file (on importSettings dialog)
  WRITES TO [FS]:
    - orbit_tracker.log  (via appendFileSync fallback before Python is up)
  SPAWNS:
    - src/backend/monitor.py  [stdio]  (dev mode: python ./src/backend/monitor.py)
    - dist/orbit_monitor.exe  [stdio]  (production: PyInstaller bundle)
  SENDS [IPC] to renderer (via webContents.send):
    - "tasks-list"        after every task mutation
    - "settings-map"      after getSettings / saveSetting
    - "monitor-update"    forwarded from Python stdout
    - "focus-started"     forwarded from Python stdout
    - "focus-stopped"     forwarded from Python stdout
    - "research-complete" forwarded from Python stdout
    - "heartbeat"         forwarded from Python stdout
    - "monitor-status"    on Python crash/reconnect
    - "focus-messages"    after loadFocusMessages() reads .txt file
    - "settings-imported" / "settings-exported"  after file dialogs
  RECEIVES [IPC] from renderer (via ipcMain.on "task-action"):
    - changeMode    -> creates/hides BrowserWindows
    - getFocusMessages -> reads focusModemsgs.txt, sends back
    - exportSettings / importSettings -> dialog + file I/O
    - everything else -> forwarded to Python via stdin
  RECEIVES [stdio] from Python stdout:
    - every JSON line: { channel, data } -> forwarded to open windows
  CONNECTED TO:
    - src/preload/preload.js  (referenced as webPreferences.preload)
    - src/renderer/ (loaded via loadURL or loadFile)
    - src/backend/monitor.py (spawned as child process)


================================================================================
  LAYER 2 — SECURITY BRIDGE
================================================================================

src/preload/preload.js
  ROLE: Context-isolated bridge. The ONLY file that touches both
        Node (ipcRenderer) and the browser window context. Exposes a
        strict whitelist API as window.electronAPI.
  DEPENDS ON (Electron):
    - contextBridge, ipcRenderer
  EXPOSES to renderer as window.electronAPI:
    - sendTaskAction(action, payload)
        Whitelisted actions: getAllTasks, createTask, completeTask,
        deleteTask, startFocus, stopFocus, getSettings, saveSetting,
        changeMode, getResearch, exportLogs, importSettings,
        exportSettings, getFocusMessages
        -> ipcRenderer.send("task-action", { action, payload })
    - onReceiveFromMain(channel, callback)
        Whitelisted channels: monitor-update, tasks-list,
        research-complete, focus-started, focus-stopped, settings-map,
        setting-saved, settings-imported, settings-exported,
        focus-messages, monitor-status, heartbeat
        Calls ipcRenderer.removeAllListeners(channel) before registering
        (prevents listener duplication from the renderer side)
    - writeLogEntry(level, message) -> ipcRenderer.send("write-log", ...)
    - openLogFile() -> ipcRenderer.send("open-log-file")
  CONNECTED TO:
    - main.js (receives its IPC messages)
    - All renderer components (consumes window.electronAPI)

src/renderer/App.jsx
  ROLE: Root component. Owns ALL global state. Routes between views.
        Registers all IPC listeners. Drives mode transitions.
  STATE OWNED:
    - currentMode        "dashboard" | "orbit"
    - activeTab          "tasks" | "analytics" | "settings"
    - taskList[]         all tasks from DB
    - activeTask         currently focused task object
    - settings{}         key-value map from DB settings table
    - focusMessages[]    parsed focusModemsgs.txt strings
    - isFocusActive      bool
    - monitorUpdate      last Python monitor-update payload
    - todayFocusSeconds  accumulated from monitor-update isOnTask ticks
    - monitorStatus      "connected" | "reconnecting" | "offline"
    - toast              { show, type, message }
    - isMobileMenuOpen   bool
  DEPENDS ON:
    - react (useState, useEffect)
    - window.electronAPI (from preload.js)
    - ./components/DashboardView.jsx
    - ./components/OrbitView.jsx
    - ./components/AnalyticsView.jsx
    - ./components/SettingsView.jsx
  IPC LISTENERS REGISTERED (via window.electronAPI.onReceiveFromMain):
    - "tasks-list"        -> setTaskList, refreshes activeTask
    - "settings-map"      -> setSettings
    - "monitor-update"    -> setMonitorUpdate, accumulates todayFocusSeconds
    - "focus-started"     -> setIsFocusActive(true), setActiveTask
    - "focus-stopped"     -> setIsFocusActive(false), clears activeTask
    - "focus-messages"    -> setFocusMessages
    - "monitor-status"    -> setMonitorStatus
    - "heartbeat"         -> resets monitorStatus to "connected"
    - "settings-imported" -> re-fetches settings, shows toast
    - "settings-exported" -> shows toast
  IPC ACTIONS SENT on mount:
    - getAllTasks, getSettings, getFocusMessages
  PROPS PASSED DOWN:
    -> DashboardView: taskList, activeTask, isFocusActive,
                      monitorUpdate, focusMessages
    -> OrbitView:     taskList, activeTask, monitorUpdate,
                      isFocusActive, focusMessages, onBackToDashboard
    -> AnalyticsView: taskList, todayFocusSeconds, triggerToast
    -> SettingsView:  settings
  CONNECTED TO:
    - All 4 view components (conditional renders)
    - preload.js window.electronAPI

  LAYER 4 — PYTHON BACKEND
================================================================================

src/backend/monitor.py
  ROLE: Python subprocess. Single long-running process that handles all
        DB operations, window monitoring, web research, and audio beeps.
        Communicates exclusively via stdin (receive) / stdout (send).
  GLOBAL STATE:
    - activeTask     dict | None
    - focusActive    bool
    - monitorThread  Thread | None
    - soundThread    Thread | None
    - dbFilePath     str  (default "orbit_tracker.db", updated by setPaths)
    - logFilePath    str  (default "orbit_tracker.log", updated by setPaths)
  DEPENDS ON (Python stdlib):
    - os, sys, json, time, random, threading, traceback, datetime
  DEPENDS ON (Python third-party, optional):
    - win32gui, win32process  (pywin32) — active window handle
    - psutil                  — process name from PID
    - winsound                — accountability beep
    - duckduckgo_search       — web research (DDGS class)
    - db.py                   — all SQLite operations (local import)
  THREADS SPAWNED:
    - heartbeatThread()       daemon, sends heartbeat every 5s forever
    - monitorFocusLoop()      daemon, runs while focusActive==True
    - playAccountabilityBeeps() daemon, runs while focusActive==True
    - performWebResearch()    daemon, per-task on createTask
  STDIN ACTIONS HANDLED:
    - setPaths        { dbPath, logPath }  -> updates globals, createTables, pruneOldLogs
    - getAllTasks      -> db.getAllTasks -> sendToElectron("tasks-list", ...)
    - createTask      { title, ... }  -> db.createNewTask, getAllTasks, research thread
    - completeTask    { taskId }  -> db.updateTask(is_completed=1)
    - deleteTask      { taskId }  -> db.deleteTask
    - startFocus      { taskId }  -> starts monitorThread + soundThread
    - stopFocus       -> sets focusActive=False
    - saveSetting     { key, value }  -> db.saveSetting, sends updated settings-map
    - getSettings     -> db.getSettings -> sendToElectron("settings-map", ...)
    - getResearch     { taskId }  -> db.getWebResearch -> sendToElectron("research-complete", ...)
    - exportLogs      -> db.exportLogsToCSV to ~/Desktop/orbit_focus_logs.csv
    - exportSettingsFile { filePath }  -> writes JSON settings file
    - logEntry        { level, message }  -> writes to log file
  STDOUT CHANNELS EMITTED:
    - "heartbeat"         every 5s
    - "tasks-list"        after any task mutation
    - "settings-map"      after any settings change
    - "monitor-update"    { taskId, appName, windowTitle, isOnTask, interval }
    - "focus-started"     { taskId }
    - "focus-stopped"     { status }
    - "research-complete" { taskId, tips }
    - "paths-initialized" { status }
    - "settings-exported" { success }
  CONNECTED TO:
    - main.js (parent process via stdio)
    - db.py (direct import, all DB calls go through it)
    - orbit_tracker.db (via db.py)
    - orbit_tracker.log (direct file write)

src/backend/db.py
  ROLE: Pure SQLite wrapper. No threads, no I/O beyond the DB file.
        All functions take a connection as first arg and return plain
        Python dicts/lists. Called exclusively by monitor.py.
  DEPENDS ON (Python stdlib):
    - os, sqlite3, json, datetime, csv
  DATABASE FILE:
    - orbit_tracker.db (path passed in at runtime)
  TABLES MANAGED:
    - tasks           id, title, description, notes, priority, tags,
                      type, interval_days, target_apps, color,
                      is_completed, created_at, completed_at
    - time_logs       id, task_id (FK), timestamp, duration_seconds,
                      is_on_task, app_name, window_title
    - web_research    id, task_id (FK UNIQUE), tips (JSON), updated_at
    - settings        key (PK), value
  INDEXES:
    - idx_time_logs_task_id
    - idx_time_logs_timestamp
  FUNCTIONS EXPORTED:
    - getDatabaseConnection(dbPath)  -> connection (WAL mode, Row factory)
    - createTables(connection)       -> schema init + user_version=1
    - pruneOldLogs(connection, days) -> DELETE old time_logs
    - exportLogsToCSV(connection, csvFilePath)
    - createNewTask(connection, title, ...)  -> lastrowid
    - getAllTasks(connection)        -> list[dict]
    - updateTask(connection, taskId, **fields)
    - deleteTask(connection, taskId)
    - logTimeSpent(connection, taskId, duration, isOnTask, appName, title)
    - saveWebResearch(connection, taskId, tips)
    - getWebResearch(connection, taskId)  -> dict | None
    - getSettings(connection)  -> dict
    - saveSetting(connection, key, value)
  CONNECTED TO:
    - monitor.py (only caller)
    - orbit_tracker.db (SQLite file on disk)

================================================================================
  DATA FLOW SUMMARY
================================================================================

USER ACTION (e.g. create task)
  -> DashboardView.jsx  calls window.electronAPI.sendTaskAction("createTask", ...)
  -> preload.js         validates action, sends ipcRenderer.send("task-action", ...)
  -> main.js            receives ipcMain.on("task-action"), forwards to Python stdin
  -> monitor.py         reads from sys.stdin, calls db.createNewTask()
  -> db.py              executes INSERT INTO tasks, commits to orbit_tracker.db
  -> monitor.py         calls db.getAllTasks(), sends JSON to sys.stdout
  -> main.js            readline reads Python stdout line, calls
                        dashboardWindow.webContents.send("tasks-list", data)
  -> preload.js         ipcRenderer.on("tasks-list") fires callback
  -> App.jsx            setTaskList(tasks) -> re-renders DashboardView + OrbitView

FOCUS SESSION START
  -> DashboardView.jsx  sendTaskAction("startFocus", { taskId })
  -> main.js            forwards to Python stdin
  -> monitor.py         sets focusActive=True, spawns monitorFocusLoop thread
  -> monitorFocusLoop   every N seconds: win32gui.GetForegroundWindow()
                        -> db.logTimeSpent() -> sendToElectron("monitor-update", ...)
  -> main.js            forwards to all open windows
  -> App.jsx            setMonitorUpdate -> re-renders OrbitView / FocusModeOverlay
  -> FocusModeOverlay   if !isOnTask: shows distraction alert modal

WINDOW MODE SWITCH (orbit)
  -> App.jsx            handleModeTransition("orbit") -> sends changeMode IPC
  -> main.js            createOrbitWindow() OR orbitWindow.show()
                        dashboardWindow.hide()   <-- NOTE: hide not close
                        (BUG: RAM does not drop)
